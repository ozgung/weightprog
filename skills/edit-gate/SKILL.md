# The edit gate

The gate answers one question with a rule fixed in advance: on data no proposer saw, does a frozen edit change the
targeted behaviour more than random edits of the same size, without breaking what already worked?

## 1. Pre-register (before any candidate is generated on the gate set)

`weightprog prereg > prereg.md`, fill every field, commit it and record sha256s of: the key file, the analysis code
(weightprog version/commit), the GateSpec JSON. Decide and write down:

- **Gate set held out by repository**, not just by task. The study used 320 calls from 101 tasks in 69 repositories
  that no proposer saw; proposers had four other repositories.
- **Universe and draws**: keys file x draws (greedy + one sampled at the served settings), seed policy.
- **Family**: the candidates and Holm m; a run whose final edit is empty is not a candidate and holds a p = 1 slot.
- **References**: one shared base arm; for each candidate, matched random controls (`weightprog controls`, same
  modules, ranks and per-module Frobenius norm) with seeds `SEED_BASE + 10 i + k`.
- **Rule** (`GateSpec`): primary metric and direction; guards (non-inferiority margin, preservation of base
  successes per draw, compile margin); fixed-sequence secondary.
- **What each outcome means**, in words, including "primary passes, a guard fails = not a pass".
- **Disclose every look** at the gate set before freezing (the study disclosed the base arm's artefact count).

## 2. Freeze and generate

Copy each candidate's `edit/` into `GATE/<cand>/edit` and make it read-only before generating (record
`shasum -a 256`). Generate every arm with the same backend, dtype, seeds and replay mode:

```bash
weightprog replay frozen --backend mlx --model-dir M --calls C --keys K --draws 2 --out GATE/gen_base.jsonl
weightprog controls GATE/cand GATE/cand_rand1 --seed S1 ; weightprog controls GATE/cand GATE/cand_rand2 --seed S2
weightprog replay frozen ... --edit GATE/cand/edit --out GATE/gen_cand.jsonl     # and for each control
weightprog score frozen GATE/gen_<arm>.jsonl --calls C --files F [--replacer swegemma]
```

Never mix backends (or dtypes) across arms of one analysis: sampled draws differ by RNG.

## 3. Run the rule

```bash
weightprog gate --gate-dir GATE --keys K --calls C --files F --m 2 --spec gatespec.json --report report.json cand1 cand2
```

It BLOCKs (no report) on duplicate records, missing or extra (key, draw) rows, an edit arm whose rows do not name its
own frozen edit directory, or a base row with an edit. Do not "fix" a BLOCK by dropping rows: regenerate.

## 4. The compile trap and the full-call amendment

A frozen-prefix replay keeps whatever the served model wrote before the regenerated argument. For Gemma 4's
`edit_file` that includes new_string (arguments are written in sorted key order). An edit that turns an escaped
old_string into an exact copy then pairs a clean old_string with a still-escaped new_string, and the harness inserts
it verbatim: compile failures that the edited model would not produce. Measure compile on a full-call replay
(`weightprog replay fullcall`, both arguments generated by the arm) and amend only that guard
(`weightprog amend --report report.json cand ...`). If you amend after registration, write a dated amendment stating
what had been looked at, and report both verdicts.

## 5. Report

- Both verdicts if amended; the primary table vs base and each control; guards with their limits; the bootstrap CIs
  (task and repository-clustered) as description; the per-recorded-kind table (what the edit gained and broke).
- The study's wording for its result: "two frozen, gradient-free edits reduced the targeted failure on held-out
  repositories beyond matched random edits of the same size; neither did so without collateral loss on calls the
  base already copied correctly; no edit passed the registered gate." Keep claims about downstream task success out
  unless a separately registered agent-level test shows them.
- A null is reported with its scope: "no demonstrated benefit under this budget and protocol", not "equivalent to
  random" (the sign test does not test equivalence).

## Statistics (exact, `weightprog.stats`)

- Unit: the task (mean over its calls x draws); paired differences edit - reference.
- One-sided exact sign test: p = P(Bin(n+ + n-, 1/2) >= n_better), zeros dropped; p = 1 when all are zero.
- Holm step-down over the family size m; the secondary is tested only for primary passes (p = 1 otherwise).
- Bootstrap: 10,000 resamples of tasks (seed S) and of repositories (seed S + 1), 2.5 / 97.5 percentiles.
